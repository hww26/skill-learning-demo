# concept-learning-generator：AI 概念学习资料生成器

接收一个 AI 相关概念名称，产出一份结构化、可查证、大白话优先的学习资料（Markdown）。本技能是通用模板，适用于任何新概念。

## 触发条件

- 用户要求"给我讲讲 X / 生成 X 的学习资料 / 完整解释 X"
- 用户点名本技能（concept-learning-generator）

## 执行流程

1. **解析输入**：确认概念名。若概念有歧义（如 "Skill" 既可指 Claude Skill 也可指一般技能），按 AI 领域当前最通行的含义处理，并在资料开头注明采用的定义口径。
   - 若输入是**多个概念之间的关系**（如 "Agent、上下文、Skill 三者关系"），仍按同一八节结构生成：第 1、2 节围绕"关系"本身展开（分工、协作机制、咬合方式），第 4 节做概念间对比；已有单概念资料的，在文中注明可对照阅读，不重复展开细节。
2. **查证调研**（生成前必做，不可跳过）：
   - 用 WebSearch / WebFetch 查 2-4 个权威来源：官方文档、arXiv 论文、知名开源仓库、一线工程博客
   - 第 5 节只放真实存在且查证过的链接，查不到的一律不写
   - 技术事实拿不准时：能查则查；查不到就在文中标注"待验证"，不得写成确定结论
3. **按固定结构生成** Markdown（见下节），全文简体中文，术语首次出现给英文原词。
4. **输出**：输出位置与格式**以用户当次指令优先**。用户指定了保存路径/格式时，严格按要求生成（如自包含 HTML 页面，风格与本仓库 `learning-materials/` 既有资料保持一致）；未指定时默认直接在对话中输出完整 Markdown，若用户要求存档，保存到仓库 `study-notes/<概念名>.md`，并按仓库流程 git 提交推送。

## 输出固定结构（顺序不可变，标题原样保留）

```text
# <概念名> 学习资料

## 学习目标
3-5 条，用"学完能够…"句式，具体可检验。

## 1. 个人理解解释
先一句话大白话定义，再用一个生活/工程类比建立直觉，最后交代它在 AI 技术版图中的位置。禁止用术语解释术语。

## 2. 核心机制 / 组成
分点拆解：由哪些部分组成、数据与控制如何流动、关键步骤是什么。可用表格、编号流程或简短伪代码。

## 3. 真实落地应用场景
2-4 个真实案例（具体产品/公司/开源项目 + 它如何使用该概念）。不编造案例；不确定的案例删掉。

## 4. 易混淆点 & 使用边界
- 易混淆：与 1-3 个相近概念对比，用表格（维度 | 本概念 | 相近概念）
- 使用边界：哪些场景不适合、常见误用是什么

## 5. 可查证的正规参考来源链接
3-6 条，每条格式：`- [标题](URL) —— 一句话说明来源性质（官方文档/论文/仓库）`。宁缺毋滥。

## 6. 核心思考题
2-3 道开放式问题，指向机制取舍、适用边界等深层理解，不给标准答案。

## 7. 自测小题（附答案）
3-5 道客观或简答题，覆盖易错点；答案与一句话解析集中放在本节末尾。
```

## 质量红线

- 参考链接不可编造：每条链接必须经过查证，无法验证 URL 的来源直接删除
- 类比必须准确映射到机制本身，避免造成错误直觉
- 结构顺序与标题固定，不得增删大节
- 输入概念若明显不属于 AI 领域，向用户提示后仍按同一结构尽力生成
- 概念随时间演进快时（如模型版本、API 名称），在文中注明"以官方文档最新版为准"
